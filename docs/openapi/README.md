# OpenAPI Specs

OpenAPI 3.0.3 specs for four services, generated by
`web/dashboard/scripts/generate-openapi.mjs` from definitions in that script.
Edit the script, never the generated files.

| Spec | Service | Edge base path | Dashboard viewer |
|---|---|---|---|
| `sbom.openapi.{yaml,json}` | sbom (SBOM, CBOM, PQC readiness) | `/svc/sbom` | `/openapi/sbom.html` |
| `posture.openapi.{yaml,json}` | posture (dashboard, findings, risk, remediation actions) | `/svc/posture` | `/openapi/posture.html` |
| `compliance.openapi.{yaml,json}` | compliance (posture, assessments, templates) | `/svc/compliance` | `/openapi/compliance.html` |
| `reporting.openapi.{yaml,json}` | reporting (report jobs, alert MTTD/MTTR stats) | `/svc/reporting` | `/openapi/reporting.html` |

Each spec covers a subset of its service's routes. The full list of routes
every service registers is the generated route index in
[../API_REFERENCE.md](../API_REFERENCE.md).

Regenerate, then check the committed files match:

```bash
npm --prefix web/dashboard run generate:openapi
```

```bash
npm --prefix web/dashboard run validate:openapi
```

`generate:openapi` also copies Swagger UI from `node_modules`; run `npm ci`
first so it matches the lockfile.

What is checked:

- `validate:openapi` (CI "Validate OpenAPI artifacts"): the committed files
  match the generator's output.
- `scripts/check-doc-routes.py` (`make conformance`): every server is an edge
  `/svc/<name>` path routed to a service, and every operation is a route that
  service registers.
- Not checked: that parameters, request bodies and response schemas match the
  handlers.
